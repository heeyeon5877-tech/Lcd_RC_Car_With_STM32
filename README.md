## 배경 및 목적

STM32 마이크로컨트롤러(STM32F411RE) 기반의 임베디드 시스템을 직접 설계·구현하며 하드웨어-소프트웨어 통합 경험을 쌓기 위해 시작한 프로젝트입니다. 단일 센서/모터 제어를 넘어, 여러 주변장치(초음파, IMU, LCD, 조도센서, PWM 출력)를 하나의 시스템에서 동시에 다루는 실전형 프로젝트를 목표로 설계했습니다.

**목적**

1. 초음파 센서(HC-SR04)로 장애물 유무를 감지하는 RC카 제어 로직 구현
2. 가속도계(ADXL345)의 기울기 값을 이용해 LCD 화면 이미지를 상태 기반으로 전환
3. 조도센서(LDR) 기반 자동 밝기 조절 LED 시스템 구현
4. 여러 타이머·인터럽트·통신 프로토콜(I2C, SPI, UART, ADC, PWM)을 하나의 펌웨어 안에서 충돌 없이 통합 운용하는 능력 습득
5. STM32CubeMX + HAL 기반으로, 타이머 인터럽트에서 플래그를 세우고 메인 루프에서 소비하는 구조를 통해 실시간성과 코드 안정성을 함께 확보

## 시스템 개요

STM32F411RE 두 대가 UART(비동기 시리얼)로 연결되어 있으며, 각각 **Controller 보드**와 **Car 보드**로 역할이 나뉩니다.

```
[Controller Board · STM32F411]              [Car Board · STM32F411]
조이스틱 X/Y축                                UART RX 인터럽트 (링버퍼)
   │                                              │
   ▼                                              ▼
ADC + DMA (10ms 샘플링)                       패킷 파싱 (Fail-safe 500ms)
   │                                              │
   ▼                                              ▼
10-sample 이동평균 필터                       목표 RPM 변환 (V/W Mixing)
   │                                              │
   ▼                              UART1           ▼  ← 초음파 HC-SR04 10cm 이내 시 전진 차단
패킷 생성 (100ms)               ────────►   ┌─────────────┴─────────────┐
AA·55·X_H·X_L·Y_H·Y_L·LED         9 Bytes   ▼                           ▼
                                       엔코더 좌 (TIM1)             엔코더 우 (TIM3)
                                             │                           │
                                             ▼                           ▼
                                          PID 좌                      PID 우
                                             │                           │
                                             ▼                           ▼
                                       PWM (TIM4 CH1)             PWM (TIM4 CH2)
                                             │                           │
                                             ▼                           ▼
                                          좌측 모터                   우측 모터

                                       상태 표시 ───────────────────────
                                       ADXL345 IMU (I2C, 50ms)
                                             │
                                             ▼
                                       기울기 → 좌표 변환 (Easing)
                                             │
                                             ▼
                                       ILI9341 TFT (SPI, 캐릭터 애니메이션)
```

### UART 패킷 포맷 (9 Bytes)

| AA | 55 | X_H | X_L | Y_H | Y_L | LED | \n | \r |
|----|----|-----|-----|-----|-----|-----|----|----|
| 시작바이트1 | 시작바이트2 | X축 상위 | X축 하위 | Y축 상위 | Y축 하위 | LED 플래그 | 개행 | 캐리지리턴 |

Car 보드는 수신 링버퍼에서 `0xAA 0x55` 시작 시퀀스를 탐색해 9바이트 패킷을 잘라낸 뒤 파싱합니다. 500ms 이상 정상 패킷이 없으면 정지 명령으로 대체(Fail-safe)됩니다.

### 제어 루프 타이밍 (TIM5, 1ms tick 기반 소프트 타이머)

| 주기 | 처리 내용 |
|------|-----------|
| 10ms | 조이스틱→목표 RPM 계산, 장애물 체크, 엔코더 RPM 읽기, PID 연산, 모터 출력 |
| 50ms | UART 패킷 파싱/Fail-safe 판정, IMU 읽기, LCD 캐릭터 위치 갱신 |
| 100ms | 초음파 트리거 발사(Car) · 조이스틱 패킷 송신(Controller) |

### PID 게인 (좌/우 동일)

| 항목 | 값 |
|------|-----|
| Kp (비례) | 3.00 |
| Ki (적분) | 0.05 |
| Kd (미분) | 0.00 |
| 출력 클램프 | ±999 |
| 엔코더 PPR | 1320 |

## 하드웨어 구성

### Car (2WD 구동부 + 센서·디스플레이 통합)

2단 아크릴 섀시에 좌/우 DC 모터와 엔코더를 장착하고, 모터 드라이버를 통해 TIM4 PWM 신호로 속도를, 방향 GPIO로 정·역전을 제어합니다. 전면 하단에는 HC-SR04 초음파 센서를 배치해 진행 방향의 장애물을 감지하고, 상단 중앙의 ILI9341 TFT LCD가 IMU 기울기에 반응하는 캐릭터를 표시합니다.

STM32F411RE Nucleo 보드를 중심으로 브레드보드에서 모터 드라이버·ADXL345 IMU·초음파 센서 배선을 분기하였고, 블루투스 모듈을 UART에 연결해 조종기로부터 제어 패킷을 무선 수신합니다.

### Controller

만능기판 위에 STM32F411RE Nucleo 보드와 2축 아날로그 조이스틱, LED 제어용 푸시버튼을 배치하여, 조이스틱 X/Y 값을 ADC로 읽어 전후진·회전 명령으로 변환합니다. AA 건전지 홀더로 독립 전원을 구성해 PC 연결 없이 동작하며, 블루투스 모듈을 UART에 연결해 100ms 주기로 제어 패킷을 무선 송신합니다.

### 부품 목록

| 모듈 | 통신 방식 | 역할 |
|------|-----------|------|
| HC-SR04 (초음파) | GPIO (Trig/Echo, TIM2 Input Capture) | 전방 장애물 감지 (10cm 이내 전진 차단) |
| ADXL345 (가속도계) | I2C1 | 차체 기울기 감지 → LCD 캐릭터 반응 |
| ILI9341 TFT LCD | SPI1 | 상태/캐릭터 애니메이션 표시 |
| 조도센서 (LDR ×2) | ADC | 밝기 감지 → LED PWM 자동 조절 |
| 엔코더 (좌/우) | TIM1 / TIM3 (Encoder 모드) | 모터 RPM 피드백 |
| DC 모터 ×2 | PWM (TIM4 CH1/CH2) | 좌/우 구동 |
| 블루투스 모듈 | UART | Controller ↔ Car 무선 통신 |
| 조이스틱 (2축 아날로그) | ADC + DMA | 조종 입력 |

## 소프트웨어 구조

- **Project_Controller**: 조이스틱 입력 → ADC → 패킷 송신
- **Project_Car**: 패킷 수신 → PID 모터 제어 + IMU/초음파 센서 + TFT LCD 디스플레이

각 모듈은 드라이버 파일 단위로 분리되어 있습니다: `adxl345.c/.h`, `hcsr04.c/.h`, `ldr_led.c/.h`, `ili9341.c/.h`, `pid.c/.h`, `encoder.c/.h`, `motor.c/.h`, `joystick.c/.h`, `adc_to_rpm.c/.h`, `packet.c/.h`

## 주요 기능 구현

### 1. PID 기반 모터 속도 제어
`pid.c`, `encoder.c`, `motor.c`

1. 좌/우 바퀴에 엔코더(TIM1/TIM3 Encoder 모드)를 달아 10ms 주기로 카운트 변화량 → RPM 환산 (`ENCODER_PPR=1320`)
2. 조이스틱에서 계산된 목표 RPM을 `set_target()`으로 PID에 입력
3. PI 제어(Kp=3.0, Ki=0.05, Kd 미사용)로 목표 RPM과 실제 RPM의 오차를 보정, 적분 와인드업 방지를 위한 출력 클램핑(±999) 및 데드밴드(출력 100 이하 무시) 적용
4. 계산된 출력값을 TIM4 PWM(Duty)으로 좌우 모터 드라이버에 전달, 방향 GPIO로 정/역전 제어

### 2. IMU (ADXL345)
`adxl345.c`

1. ADXL345를 I2C로 초기화 (`DATA_FORMAT` → `POWER_CTL` 순서 준수)
2. 50ms 주기로 X/Y/Z 가속도 원시값을 읽어와 차체 기울기 감지
3. 이 값을 TFT LCD의 캐릭터(눈/얼굴) 좌표로 매핑해 기울기에 반응하는 UI 연출에 사용

### 3. 초음파 센서 (HC-SR04)
`hcsr04.c`

1. 100ms마다 TRIG 핀에 펄스 발생 → Echo 핀을 TIM2 Input Capture(Rising/Falling)로 캡처해 펄스폭 측정
2. 펄스폭(us)/58 = 거리(cm) 환산, 10cm 이내 장애물 감지 시 전진 방향 목표 RPM을 강제로 0으로 만들어 충돌 방지 (후진/회전은 허용)

### 4. 조이스틱 기반 무선 조종
`joystick.c`, `adc_to_rpm.c`, `packet.c`

**Controller 측**
1. ADC(DMA)로 조이스틱 X/Y 축 값을 10ms마다 읽어 10개 샘플의 이동평균 필터(`iXValueBuff`/`iYValueBuff`) 적용 → 떨림/노이즈 제거
2. 100ms마다 `0xAA 0x55`(시작바이트) + X상위/하위 + Y상위/하위 + LED플래그 + `\n\r` 형식의 9바이트 패킷을 UART1로 송신

**Car 측**
1. UART1 인터럽트 수신(`HAL_UART_RxCpltCallback`)으로 링 버퍼에 1바이트씩 적재
2. `packet.c`의 `findStartByteInBuffer`/`isPacketInBuffer`로 버퍼 내 시작바이트(0xAA, 0x55) 위치를 찾아 완전한 패킷을 잘라내고 파싱
3. 500ms 이상 패킷 수신 실패 시 자동 정지(Fail-safe) 처리
4. 파싱된 X/Y 조이스틱 값 → `calculate_target_RPM()`(`adc_to_rpm.c`)에서 데드존 처리 후 전후진(V)/회전(W) 성분으로 분리, 좌우 바퀴 목표 RPM으로 변환 (differential drive mixing: `left = V-W`, `right = V+W`)

### 5. TFT LCD 상태 디스플레이
`ili9341.c`

1. ILI9341 LCD를 SPI로 구동, 화면 회전/배경색 초기화
2. IMU 가속도 값을 화면 좌표로 정규화(데드존 + 3제곱 이징 곡선 적용해 부드러운 움직임) 후, 기울기 방향에 따라 좌/우/정면 이미지(`left_img`/`right_img`/`center_img`)를 전환하며 캐릭터 위치를 갱신
3. 이전 위치와 겹치는 부분만 배경색으로 지우는 부분 갱신(dirty-rect) 방식으로 깜빡임 없이 애니메이션

### 6. 조도센서 기반 자동 LED 밝기 조절
`ldr_led.c`

LDR(×2)로 주변 밝기를 ADC로 측정하고(`4095 - adc_avg`로 반전 처리), 값을 PWM 스케일링해 TIM4 채널을 통해 LED 밝기를 자동 조절합니다.

## 결과 및 회고

**초기 목표 기능 구현 완료**
STM32F411RE 두 대를 UART로 연결해 조이스틱 입력 → 패킷 송수신 → PID 기반 좌우 모터 속도 제어까지 이어지는 제어 파이프라인을 10ms 주기로 안정적으로 동작시켰습니다. 여기에 초음파 10cm 장애물 정지, 500ms Fail-safe, IMU 기울기에 반응하는 TFT LCD 캐릭터 애니메이션까지 통합하여 시연 영상으로 실제 주행을 검증했습니다.

**리소스 설계와 통합 역량 확보**
TIM1~TIM5를 엔코더·PWM·Input Capture·소프트 타이머로 나누어 배분하고, I2C·SPI·UART·ADC를 하나의 펌웨어에서 충돌 없이 운용하는 경험을 얻었습니다. 특히 1ms 소프트 타이머로 10ms/50ms/100ms 주기를 분리한 구조 덕분에, 제어 주기와 표시·통신 주기를 독립적으로 조정할 수 있어 기능 추가 시 부담이 크게 줄었습니다.

**아쉬운 점: 물리 계층 오류에 소요된 시간**
SD카드 배선 미스, LCD MISO 플로팅, CS 핀 충돌 사례처럼 이번 프로젝트의 병목은 대부분 코드가 아닌 배선에 있었습니다. 초기 하드웨어 설계 및 배선 검토에 충분한 시간을 배분하는 것이 결과적으로 전체 개발 속도를 높이는 길이라는 점을 체감했습니다.

## 향후 과제

**미완 과제: OV7670 카메라 & SD카드 영상 저장**

추가 기능으로 계획했던 카메라 모듈 연동과 SD카드 영상 저장은 기간 내 완성하지 못해 최종 시스템에서 제외했습니다. I2C Bus Recovery 절차와 레지스터 Read 방식 수정으로 카메라 통신 확보까지는 성공했으나, DCMI로 수신한 영상이 정상적인 해상도·비율로 들어오지 않아 PC 출력 화면이 실제 비율과 다르게 나타나는 문제가 남아 있습니다.

- 향후 OV7670의 해상도 설정과 HSTART/HSTOP, 스케일링 관련 레지스터를 조정해 정상 비율 수신을 구현할 계획입니다.
- 문제가 지속될 경우 다른 카메라 모듈로 변경할 예정입니다.
- 이후 SD카드 저장 파이프라인까지 연결하여 주행 영상 기록 기능을 완성하고자 합니다.

## 실행 방법

### 1. 개발 환경

- STM32CubeIDE 또는 VS Code + cube-cmake
- STM32CubeMX (`.ioc` 파일이 설정의 source of truth)
- STM32 HAL 라이브러리

```bash
git clone https://github.com/heeyeon5877-tech/Lcd_RC_Car_With_STM32.git
```

### 2. 빌드 및 플래시

1. IDE에서 `Project_Controller`, `Project_Car` 각각 프로젝트 Import
2. Build
3. ST-Link를 통해 각 STM32F411RE 보드에 Flash (Controller 보드 / Car 보드 각각)

### 3. 하드웨어 연결 및 동작 확인

1. Car 보드에 모터, 엔코더, HC-SR04, ADXL345, ILI9341, LDR/LED, 블루투스 모듈 연결
2. Controller 보드에 조이스틱, 푸시버튼, 블루투스 모듈 연결
3. 두 보드의 블루투스 모듈 페어링
4. Controller 전원(AA 건전지) 인가 후 조이스틱으로 조종, LCD·LED 반응 확인
